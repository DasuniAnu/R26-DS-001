SINHALA YOUTUBE CONTENT CONSISTENCY DETECTION
Panel Presentation Kit

Recommended duration: 8–10 minutes presentation + demonstration + questions


CORE MESSAGE

This project is an end-to-end Sinhala-first screening system that checks whether a YouTube video's title and description are supported by its transcript. Its contribution is not an unsupported claim of perfect fact-checking; it is a practical, evidence-aware workflow that connects data collection, text processing, classification, human-review signals, a web interface, an API, and a Chrome extension.

SLIDE 2 — THE PROBLEM IS A MISMATCH BETWEEN PROMISE AND CONTENT

Visible content

Viewers often decide whether to trust or watch a video from its title and description.

The challenge:

• A dramatic title may not be supported by the transcript.
• Manual comparison is slow for long Sinhala videos.
• Sinhala-language tooling and labeled resources are limited.

Project question

Can a system automatically identify when the available transcript does not sufficiently support the video's metadata?

What to say

“I deliberately narrowed the problem. Instead of claiming to prove whether every statement in the world is true, the system asks a measurable question: does the spoken content support what the title and description promise? This makes the project technically defensible and useful as a first-stage screening tool.”


SLIDE 3 — THE OUTPUT IS A CONSISTENCY JUDGMENT, NOT A VERDICT ON TRUTH

Visible content

Inputs

Title + Description + Transcript

Output

False — the metadata is not sufficiently supported by the transcript
Not False — the available fields are aligned enough

Also returned

Confidence • class probabilities • evidence signals • review recommendation

Boundary

The system detects internal content mismatch; it does not replace external fact-checking.

What to say

“This definition is important. Here, ‘False’ means insufficient support or inconsistency between the available fields. It does not automatically mean every real-world claim in the video is false. The interface therefore gives a review recommendation instead of making an irreversible decision.”


SLIDE 4 — THE PIPELINE TURNS A YOUTUBE VIDEO INTO REVIEWABLE EVIDENCE

Visible content

1. Acquire
YouTube URL, title, description, public captions

2. Understand
Clean Sinhala text, normalize common English terms, compute cross-field similarity

3. Decide
Classify as False or Not False and calculate confidence

4. Present
Show evidence signals, warnings, and a human-review recommendation

Fallback

If captions are unavailable, the user may explicitly generate a transcript with Whisper or continue without one.

What to say

“The workflow starts from a YouTube URL or manual input. Public captions are preferred because they are faster and avoid unnecessary audio processing. If captions are missing, the user chooses whether to generate a transcript. That explicit choice is both a usability and a responsible-computing decision.”


SLIDE 5 — TEXT CONSISTENCY IS MODELED AT BOTH WORD AND CHARACTER LEVELS

Visible content

Live runtime

• Word n-grams capture meaningful phrases.
• Character n-grams handle spelling variation and mixed Sinhala–English text.
• Logistic regression provides fast, explainable, CPU-friendly inference.

Research path

• XLM-RoBERTa fine-tuning pipeline is included for deeper contextual modeling.
• The model input preserves title, description, transcript, and consistency features as separate sections.

Engineering choice

The demonstration uses the self-contained fast model so it loads reliably on ordinary hardware.

What to say

“For the live application, I use a word-and-character TF-IDF representation with logistic regression. Character features are useful for spelling variation and code-mixed text. The repository also includes an XLM-RoBERTa training path, but the fast model is the safer choice for a reliable CPU demonstration.”


SLIDE 6 — THE SYSTEM IS DESIGNED TO RESIST EASY SHORTCUTS

Visible content

Three safeguards

Group-aware splitting
Related samples stay in one split to reduce leakage.

Quality checks
Schema validation, missing-value checks, duplicate checks, balanced labels, and topic reports.

Hard cases
Same-topic examples can differ by a decisive person, number, place, product, time period, or outcome.

Evidence-aware behavior

Missing transcripts, missing sources, and low confidence trigger warnings or human review.

What to say

“A classifier can look impressive by learning shortcuts. I therefore keep related examples together during splitting and run data-quality checks before training. I also include difficult same-topic mismatches, where only one important fact changes. At inference time, weak evidence is not hidden; it produces a warning.”

PANEL Q&A — STRONG, DEFENSIBLE ANSWERS

1. Is this a fake-news detector?

“Not in the broad external fact-checking sense. The current system detects whether the title and description are sufficiently supported by the transcript. Claim verification against trusted external sources is a planned extension.”

2. Why did you choose a binary output?

“A binary output supports a clear first-stage action: allow normal viewing or recommend review. Internally I still expose probabilities, evidence signals, and review recommendations so the result is not treated as an absolute verdict.”

3. Which model is used in the live application?

“The live application prefers a self-contained TF-IDF word-and-character model with logistic regression because it is fast and reliable on CPU. The repository also contains an XLM-RoBERTa fine-tuning pipeline for deeper contextual experiments.”

4. Why use character n-grams?

“They are useful for Sinhala spelling variation, inflection, tokenization differences, and Sinhala–English code mixing. Word n-grams capture phrases, while character n-grams add robustness.”

5. What makes the project novel?

“The novelty is not a new classifier formula by itself. It is the Sinhala-first task definition and the end-to-end integration of metadata–transcript consistency, evidence warnings, caption/ASR handling, human labeling, a REST API, a web interface, and a browser extension.”

6. How did you prevent data leakage?

“The preparation pipeline uses group-aware splitting, so related examples remain in the same split. It also checks exact duplicates, repeated titles and transcripts, missing values, and label distribution.”

7. Why should we trust the accuracy?

“The current results demonstrate that the pipeline can learn the development task, but I do not present them as real-world accuracy. A trustworthy performance claim requires a larger independent human-labeled Sinhala YouTube test set. That is the next evaluation milestone.”

8. What data did you use?

Use this answer if asked directly:

“The prototype was developed primarily with a controlled generated development corpus, then supported by a small human-annotated real-video pilot. I keep those roles separate: the controlled corpus tests whether the pipeline learns the intended relationship, while an expanded independent real-video benchmark is required for real-world claims.”

Do not evade this question or describe generated samples as real YouTube observations.

9. Why is the image branch not active?

“The current corpus does not provide the real thumbnail evidence needed for a defensible multimodal result. I therefore disabled image fusion in the active version instead of presenting an artificial multimodal claim. The code path remains ready for future data.”

10. What happens when the transcript is missing?

“The system first looks for public captions. The user can explicitly request a Whisper transcript or analyze without one. Missing evidence is reported as a warning and can trigger human review.”

11. Is Whisper accurate enough for Sinhala?

“Not yet for an unconditional accuracy claim in this project. It is a fallback mechanism. The correct next step is to expand the human-transcribed test set, report WER and CER by audio condition, and validate any fine-tuned model before relying on it.”

12. Why not use only XLM-RoBERTa?

“The deep model offers contextual capacity, but the compact runtime model is faster, easier to deploy, and reliable for a live CPU demo. The architecture lets me compare that baseline with XLM-RoBERTa rather than making deployment depend on one heavy model.”

13. What are the main ethical risks?

“False positives could unfairly flag a creator, and confidence can be misunderstood. That is why the output is framed as a consistency screening result, evidence gaps are visible, and uncertain or incomplete cases are sent to human review rather than automatic enforcement.”

14. How would you evaluate it properly next?

“I would sample real Sinhala videos across topics and channels, use at least two annotators with written consistency guidelines, measure agreement, reserve an untouched grouped test set, report per-class precision and recall with confidence intervals, and analyze errors by caption source and topic.”

15. What would production deployment require?

“A larger independent benchmark, calibrated thresholds, systematic monitoring, privacy and copyright review, secure API deployment, rate limiting, model-version tracking, and an appeals or correction workflow.”
